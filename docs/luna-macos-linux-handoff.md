# Luna's macOS and Linux work list

This checklist updates the open work in [Luna's release readiness record](luna-release-readiness.md). The Tauri port and its workflows are currently local. The current version in this checkout is 2.8.15. The older 2.8.12 results in the readiness record are historical evidence. See [Terra's review](terra-release-gate-review.md) for the Apple Silicon and Ubuntu pilot results.

## First pass

1. **Repair the About fixture (L4).** In `tools/renderer-ui-harness.cjs`, derive the current and newer versions from the staged app's installed version. The hardcoded newer case (2.8.13) is older than the current app. Each scenario needs its own About open or a preceding failed check. The current script clicks Retry after a successful check has hidden that button. Cover opening About without blocking startup, offline failure and visible retry, recovery, an equal or older release with no update link, and a newer release with a browser link. Confirm the real macOS and Linux app opens the license and release links in the default browser.
2. **Get a reproducible build and save the evidence (L2, L5).** Build from a clean copy of the port revision that includes `src/web`. Use the Linux package workflow and the unsigned macOS build path. If running in GitHub Actions, use an authorized candidate branch because the workflow files are still local. Confirm staged assets and bridge load in the installed app. Save packages and hashes with the source revision, runner and webview versions, and test logs. The Linux workflow now retains packages and GUI evidence as a workflow artifact, including evidence from failed validation. Its package manifest records version, source revision, runner baseline, package names, sizes, and SHA-256 hashes. The workflow still needs a CI run before these changes are confirmed.
3. **Refresh the candidate download matrix (L5).** Read the version from Tauri metadata and the Linux filenames from `docs/linux-release-targets.json`. Use the actual Windows Intel/AMD and ARM64 labels when listing existing downloads. Verify Linux architecture, runtime dependencies (including `xdg-utils`), file associations, and desktop entry. Verify macOS bundle version, identifier, and executable slices. Prepare a draft download table and checksum manifest from real artifacts. Keep the Linux DEB first in scope and report RPM and AppImage separately until each qualifies.

## Native release checks (L6)

4. **Linux clean install and upgrade.** Run the DEB install and existing Xvfb lifecycle script on Ubuntu 22.04. Verify desktop launch and Open With on a real desktop, with GNOME Wayland and an X11 or KDE session represented. Use named distro versions for claims of support. If testing the RPM, install with DNF on Fedora and check that dependencies resolve and the app launches. For AppImage, check normal launch on each planned distro as well as the existing smoke test. On each selected package path, upgrade from an older package with the same app identity and verify theme, font, size, spacing, and page width survive. Record the specific old and new builds used.
5. **macOS install and upgrade.** Use the unsigned Apple Silicon build for functional work now. Once Terra provides a Developer ID signed and notarized DMG, verify download, Gatekeeper acceptance, install into Applications, offline launch, and replacement of an older app with preferences retained on a clean Mac. If Intel support is advertised, collect actual Intel launch and interaction evidence in addition to inspecting the universal binary.
6. **Run the same native UI checklist on both platforms.** Exercise menus, native shortcuts, and toolbar actions for New, Open, Save, Save As, Print, and About, plus Close and Quit. Cover first save, denied writes, canceled dialogs, and external file changes. Verify Finder or desktop file opens when cold, when already running with a dirty draft, and while a save is in progress. Include Unicode filenames, BOM and line endings, and relative images after Save As. Use the total torture fixture in Reader, Visual, and both Split layouts for headings, tables, narrow panes, search, undo and redo, and PDF page breaks and repeated table headers. Check clipboard and one composition method beyond the existing dead-key or compose-key pilots.
7. **Collect comparable performance evidence.** Run the Tao/Wry reference and the Tauri app on the same OS and hardware with the same renderer and torture file. Record ten cold launches each, both empty and with the file. Report median and worst time to a usable window, idle memory including webview processes, and comparable download or installed sizes. Report actual values and ratios against the plan's under-10× threshold. Use X11 for the Linux reference comparison as documented in the [build environment](cross-platform-build-environment.md).

For each check, record pass, fail, or blocked, the exact artifact and OS, and the steps needed to reproduce a failure. Send host bugs and the release evidence to Terra for T3–T7 follow-up. Terra owns signing setup, host fixes, and the release gate decision.
